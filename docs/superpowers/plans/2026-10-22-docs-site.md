# gnomon Documentation Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish all of gnomon's user-facing docs as a GitHub Pages site with a 3D sales landing, one page per AQ axis (what / why / exact formula / rubric / how to improve), rendered from a single metrics data file that a CI test keeps in sync with the scoring code.

**Architecture:** MkDocs + Material for MkDocs, themed to design system v2. All numbers and rubric text come from `docs/data/metrics.json`. They are rendered by `mkdocs-macros` functions (formula table, calibrated scale, at-a-glance rail, rubric matrix), and a stdlib `unittest` fails when that JSON drifts from `gnomon/scoring/aq.py` and `gnomon/config.py`. The landing is a standalone Material template (`overrides/home.html`) ported from the approved mockup. A new workflow builds the site on every PR and deploys it to Pages on `main`.

**Tech Stack:** Python 3.12 (docs build only), MkDocs, Material for MkDocs, mkdocs-macros-plugin, pymdown-extensions, three.js (pinned), GitHub Actions (`configure-pages`, `upload-pages-artifact`, `deploy-pages`).

**Spec:** `docs/superpowers/specs/2026-10-21-docs-site-design.md`. Approved mockups: `docs/superpowers/specs/2026-10-21-docs-site-mockup.html` (axis page) and `docs/superpowers/specs/2026-10-21-docs-landing-mockup-v2.html` (landing). Read the spec and both mockups before Task 1.

## Global Constraints

- Site URL `https://xmartlabs.github.io/gnomon/`, so `site_url` is that and every asset path is relative to it.
- English only. Plain verbs, sentence case, no marketing fluff, no inflated claims.
- Every number a reader sees on an axis, pillar, or rubric page (weights, targets, cut-offs, coverage) is rendered by a macro from `docs/data/metrics.json`. Prose never retypes those numbers.
- Never say or imply that a missing signal scores zero. Coverage states are the words "Full", "Partial (<which term>)", or "Not scored", never colour alone.
- Labels: Steering leverage shows "Not scored yet". Context intelligence's 0.60 target shows "Provisional".
- Docs tooling is never a package dependency. `pyproject.toml` stays untouched, and docs deps live only in `docs/requirements.txt`, pinned with `==`.
- `tests/test_docs_metrics_sync.py` is stdlib-only, because `ci.yml` runs `python3 -m unittest discover -s tests -v` with no installs.
- Existing workflows (`ci.yml`, `dashboard-deploy.yml`, `dashboard-image.yml`, `release.yml`) are not modified.
- Visual rules from design system v2:
  - Tokens are copied from `docs/design/design-system-v2/design_system/tokens/*.css` under the same names.
  - Archivo for language; IBM Plex Mono with `tabular-nums` for figures, labels, and code.
  - No cards; hairlines and whitespace only.
  - Full dark mode.
  - Visible focus, `prefers-reduced-motion` respected, contrast ≥4.5:1.
- Internal folders are never published: `docs/plans/`, `docs/specs/`, `docs/superpowers/`, `docs/design/`, `docs/adr/`, `docs/data/`. Neither are the three legacy files `docs/scoring-philosophy.md`, `docs/metrics-evaluation.md`, and `docs/metrics-by-source.md` while they still exist.
- Contact links: `https://www.xmartlabs.com/contact?utm_source=gnomon-docs&utm_medium=landing&utm_content=<header-cta|hero-cta|footer-cta>`. The brand link is `https://www.xmartlabs.com/?utm_source=gnomon-docs&utm_medium=landing&utm_content=brand`.
- Commits use Conventional Commits with no Co-Authored-By line. Work happens on the current feature branch, and push, PRs, and merges are the user's decisions.
- Outward-facing actions need the user's explicit OK: enabling Pages and filing GitHub issues.
- Docs build command, used everywhere below: `uv run --no-project --with-requirements docs/requirements.txt mkdocs build --strict`. The site goes to `site/`, which is gitignored.

## Review Focus

1. **Partial source.** A source missing a capability, for example Gemini on Verification, must render "Not scored" in the rail and must not show 0%. Pinned by `test_coverage_states_follow_caps` (Task 3).
2. **Withheld sibling.** On Recovery, while Steering leverage is withheld, the rail must show Recovery as 100% of Efficiency (effective), not 50%. Pinned by `test_effective_weight_redistributes_withheld_axis` (Task 4).
3. **Dark mode.** The scale, rail, and formula table must stay readable in dark mode. Pinned by the dark-mode screenshot check in Task 2 and Task 5.
4. **Narrow screens.** At 360px wide, the calibrated scale collapses to a vertical list of bands with no horizontal overflow. Pinned by the 360px screenshot check in Task 4.
5. **Included files.** Pages that include `CONTRIBUTING.md` and `dashboard/deploy/README.md` must have no broken relative links. Pinned by `mkdocs build --strict` in Task 7, plus the link rewrite step there.

### Task 3: Metrics data file and drift test

**Files:**

- Produces: `docs/data/metrics.json` with this shape. Every later task reads only these keys.

```json
{
  "contract": "19:19:19",
  "levels": [{"name": "Novice", "floor": 0}, {"name": "Apprentice", "floor": 25}, {"name": "Adequate", "floor": 45},
             {"name": "Proficient", "floor": 60}, {"name": "Advanced", "floor": 75}, {"name": "Elite", "floor": 88}],
  "sources": {"claude": {"label": "Claude Code", "caps": ["..."], "planning_scope": "measured"}},
  "pillars": [{"id": "breadth", "name": "Breadth", "weight": 30, "summary": "...", "axes": [{
    "id": "orchestration", "code_name": "Orchestration", "name": "Orchestration", "pillar": "breadth",
    "base_weight": 33, "status": "scored", "requires": ["delegate"],
    "thesis": "...", "why": "...",
    "terms": [{"name": "...", "share": 0.40, "definition": "...", "target_label": "full credit at 8 types",
               "constant": "SUBAGENT_TYPES_DISTINCT_CEILING", "value": 8, "requires": []}],
    "eligibility": "...", "code_ref": "gnomon/scoring/aq.py",
    "rubric": [{"level": "Novice", "looks_like": "...", "next": "..."}],
    "improve": "..."
  }]}]
}
```

- **`status`** is one of `scored`, `not_scored`, or `provisional`.
- **`requires`** holds capability names from `SOURCE_CAPS`, plus the pseudo-capability `planning_scope:measured`. Terms whose code passes `None` as the capability get `requires: []`.
- **`constant`** is optional. Terms with no named constant in `aq.py`, such as a plain fraction, omit both `constant` and `value`.
- **`rubric`** has exactly 6 entries in level order for `scored` and `provisional` axes, and is `[]` for `not_scored`. The `next` field is `""` on Elite.
- **`code_name`** must equal the axis name in `compute_aq`: `"Tool command (MCP + CLI)"`, `"Context Intelligence"`, and so on.

- [ ] **Step 1: Write the failing tests** in `tests/test_docs_metrics_sync.py`. Use `unittest` only: `json`, `re`, `inspect`, and `pathlib`.

  - `test_pillar_weights_match_code`: compare against the regex `build_pillar\("(\w+)", (\d+)` over `inspect.getsource(gnomon.scoring.aq.compute_aq)`. Expect `{Breadth: 30, Craft: 35, Efficiency: 20, Savvy: 15}`.
  - `test_axis_base_weights_match_code`: compare against the regex `\("([^"]+)", (\d+), \w+` over the same source. Every JSON axis `code_name`/`base_weight` pair must be found, and every code axis must exist in the JSON. There are 12 axes.
  - `test_term_constants_match_code`: for every term that has `constant`, `getattr(gnomon.scoring.aq, constant) == value`.
  - `test_levels_match_tier_floors`: `[(l["name"], l["floor"]) for l in levels]` equals `reversed(TIER_FLOORS)`.
  - `test_sources_match_config`: `set(caps) == SOURCE_CAPS[id]` and `planning_scope == gnomon.config.planning_session_scope(id)` for every key in `SOURCE_CAPS`.
  - `test_rubric_shape`: 6 entries in level order for `scored` and `provisional` axes, 0 for `not_scored`; non-empty `looks_like` everywhere; `next == ""` only on Elite.
