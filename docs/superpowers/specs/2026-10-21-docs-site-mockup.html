Metrics / Craft

Verification

Did anyone check the agent's work before it shipped? Verification counts the change sessions that ran a test and the times a review skill looked at the result.

Why it matters

An agent writes plausible code faster than a person can read it. Without a test run or a review pass in the same session, defects reach the main branch just as fast. Teams that verify inside the session catch them while the context is still loaded.

How it's computed

Two halves of equal weight. When a source can't record one half, the other carries the full axis. It is not scored as zero.

50%Tested change sessionsShare of change sessions that also ran a test command. Needs at least 5 change sessions in the month.full credit at 100%
50%Review skill useReview-type skills (code review, security review…) per tool call. Planning reviews don't count.full credit at 4 / 1,000 calls

A change session is one that wrote code and touched 2 or more files, changed 80 or more lines, or made 10 or more substantive calls. Source: gnomon/scoring/aq.py

Levels use the same cut-offs as the overall AQ tiers, so a level means the same thing on every axis.

How to improve

Write the test command into your project instructions (CLAUDE.md, AGENTS.md) so the agent runs it unprompted. Install a review skill and call it before you merge.
