Agentic Quotient · 0–100

See how well your team works with AI agents.

gnomon (γνώμων): the part of a sundial that casts the shadow. It measures by what you cast.

Shadow at 64 · Proficient

What it measures

One score from four pillars, with every weight in plain sight.

AQ = 0.30·Breadth + 0.35·Craft + 0.20·Efficiency + 0.15·Savvy

Each pillar scores 0–100 from its own axes, over one month of sessions.

30%

Breadth

How much of the agent toolkit gets used: subagents, skills, MCP servers and CLIs, and planning before work.

  • Orchestration
  • Skill fluency
  • Tool command
  • Discipline

35%

Craft

Whether the agent's work is tested, reviewed and grounded, and whether lessons get written down for the next session.

  • Verification
  • Grounding
  • Context intelligence
  • Compounding

20%

Efficiency

How the work recovers after a tool call fails.

  • Recovery
  • Steering leverageMeasured, not scored yet

15%

Savvy

Choosing models and tools with cost in mind.

  • Model mix
  • Token economy

Levels

Six levels, Novice to Elite.

The overall AQ places each developer on one ladder with fixed cut-offs.

  1. Novice0–24
  2. Apprentice25–44
  3. Adequate45–59
  4. Proficient60–74
  5. Advanced75–87
  6. Elite88–100

Fair across tools

A missing signal is never a zero.

Not every tool records every signal. When one can't, that part is left out and its weight moves to the parts that can be measured. Nobody loses points for the tool they use.

Second score

How you build, scored apart.

The GStack scorecard rates Execution, Planning and Engineering from 0 to 10, next to the AQ.

Open source
MIT license. The scoring code is public on GitHub, and the docs cite the code behind each formula.
Versioned
Every score carries a contract ID. Two scores compare only when their IDs match.
Reproducible
The miraudit skill re-derives a published score from the developer's own transcripts.

Who it's for

Leads get the team view. Developers get their own profile.

For engineering leads

Find where the team is thin.

Each developer who runs gnomon gets a profile: an AQ, a score for every pillar and axis, and a level from Novice to Elite. When developers share to your self-hosted dashboard, you see the team: average AQ, how people spread across levels, pillar averages, model mix and the trend from month to month.

The dashboard runs as one container with one volume, on your own server.

gnomon scores how someone operates agents, not the person. It is a learning aid, not a productivity ranking.

How scoring works→

For developers

Run one command and read your own profile.

gnomon reads the transcripts your agents already write to disk and opens your profile in the browser. The docs show how each number is computed and which habit moves it up.

uvx --from \ git+https://github.com/xmartlabs/gnomon@latest \ xl-ai-insights --local

Python 3 standard library only. With --local, it makes zero network calls.

Sources

Reads the agents your team already uses.

gnomon finds each tool's history where the tool already keeps it. Nothing gets installed inside the agents: no wrapper, no daemon.

What each source measures→

Privacy

The analysis runs on the developer's machine.

With --local, gnomon makes zero network calls. Code churn comes from the local git. Sharing is a separate step that each developer opts into.

Never uploaded

  • Prompts
  • File contents
  • Verbatim quotes
  • File paths
  • narrative_input.md and stats.json

Uploaded only when the developer shares

One file, summary.json, with:

  • Counts and ratios, such as error recovery, planning ratio and fan-out
  • The computed profile: AQ, archetype and scorecard
  • Names of the AI models used each month
  • Names of custom skills and MCP servers, which can include a project or customer name

With the self-hosted dashboard, shared summaries go to your own server.
